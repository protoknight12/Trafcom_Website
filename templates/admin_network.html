❓ Как се активира достъп за живо управление

Стъпки за всеки тип устройство, за да можете да зададете потребител/парола по-горе. Винаги ползвайте отделен потребител само за тази цел, с най-малко необходимите права - никога основния admin акаунт.

MikroTik (RouterOS API, порт 8728)

Тази версия на RouterOS (6.x) няма REST API - използва се старото бинарно API на порт 8728 (без TLS) или 8729 (с TLS, не се поддържа тук).

  1. В Winbox/терминал направете нова група с права само за четене + за DHCP:
    /user group add name=api-readonly policy=read,api,dhcp,test
  2. Създайте отделен потребител в тази група (не основния admin):
    /user add name=trafcom-api group=api-readonly password=<силна парола>
  3. Уверете се, че API услугата е включена:
    /ip service enable api (и по желание ограничете /ip service set api address=<IP на сървъра>, за да приема връзки само оттук)
  4. Ако устройството е с фабрични настройки (defconf), задайте му статичен management IP вместо DHCP-получен, преди да разчитате на този модул.
  5. Въведете trafcom-api + паролата в таблицата по-горе и натиснете "Тествай връзка".

Права, от които api-readonly НЕ се нуждае и не трябва да има: policy, password, reboot, ftp, sensitive - бъг в модула не бива да може да направи повече от това, което позволява самият API потребител.

Cisco IOS (SSH, порт 22)

Тези комутатори (3750/2950) са класически IOS без REST/NETCONF - връзката е през обикновен SSH.

  1. В конфигурационен режим генерирайте RSA ключ (ако още няма) и включете SSH v2:
    crypto key generate rsa modulus 2048
    ip ssh version 2
  2. Създайте отделен потребител само за тази цел (ниво 15 за show команди, не за конфигурация):
    username trafcom-api privilege 15 secret <силна парола>
  3. Разрешете вход по SSH на линиите vty:
    line vty 0 15
    login local
    transport input ssh
  4. Ако устройството иска отделна enable парола (за show mac address-table/show version в привилегирован режим), задайте я и въведете я в полето "enable парола" тук:
    enable secret <enable парола>
  5. Въведете потребителя, паролата и enable паролата по-горе и натиснете "Тествай връзка".

Ако "Тествай връзка" върне грешка за вход - най-честата причина е грешен потребител/парола/enable парола. Грешка за недостижимост - проверете дали SSH (порт 22) изобщо е отворен и достижим от този сървър.

Ubiquiti (само инвентар, без живо управление)

За Ubiquiti устройства (напр. PtP линкове) модулът пази само ръчно въведени данни - няма автоматична синхронизация през API/SSH. Реални промени по тях се правят както досега, през UniFi контролера или локалния уеб интерфейс на устройството.
